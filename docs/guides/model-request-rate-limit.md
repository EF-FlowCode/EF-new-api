# 模型请求次数限流

> 定位：现行使用与配置指南。带日期的部署或验证段落保留为当时记录；分类入口见[文档导航](../README.md)。

“系统设置 → 请求限制 → 限流”中的总次数与成功次数，同一用户的多个 API Key 共享额度。分组覆盖优先读取令牌分组，未指定令牌分组时使用用户主分组。它与[按模型 RPM](customer-tiers.md#按模型-rpm-限流)是两套独立限制。

## 计数规则

- 计数主体：请求分组在分组限流配置中有独立条目时，总次数与成功次数都按“用户 ID + 分组”单独计数；其余请求（分组未单独配置）走全局上限，并按用户 ID 共用一份计数。因此同一用户在两个各自配置了限流的分组之间互不占用，分组请求不占全局额度，全局请求也不占任一分组额度；未单独配置的多个分组仍共用全局计数，令牌分散到多个分组不会放大全局上限。内存与 Redis 两种模式规则相同。
- 总次数或成功次数为 `0` 时，对应限制关闭；时间窗口非正时跳过这两项限制。
- 先检查并登记总次数，再预占成功次数。成功限制拒绝的请求也已经消耗总次数额度。总次数保留原算法：内存使用滑动窗口，Redis 使用令牌桶。
- 成功次数准入条件为：窗口内已完成的成功数，加上正在执行的预占数，小于配置上限。检查与预占原子完成，因此并发请求不能分别看到同一个空余名额后全部进入。
- 请求正常完成后，将预占转换为成功记录，窗口从完成时刻计算。失败、panic、取消释放预占；重复完成或释放不会重复计数。
- Relay 使用最终尝试的结果，重试时清除上一尝试的流状态。HTTP 200 但最终 Relay 返回错误、流解析报错、超时、客户端断开或其他异常终止，都不计为成功。正常协议终态（包括有效的 Responses `incomplete`）仍可计成功；正常结束后主动关闭上游连接产生的清理错误不改变结果。未进入 Relay 的普通处理器沿用 HTTP 状态判断。
- Ollama 独立 NDJSON 流也发布共享流状态：缺少正常 `done` 的 EOF、读取或 JSON 错误、上游错误帧、取消和下游写出失败均不计成功。取消会关闭上游响应以解除阻塞读取；正常末帧及下游结束帧写出完成才计成功。已收到的终态 usage 保留在原结算路径，已输出内容不重放；成功名额释放不代表退款。

超限时内存与 Redis 两种模式返回同样的 429：OpenAI 格式错误体写明撞到的是总次数还是成功次数限制（含窗口分钟数与上限），并按用户 ID 写一条错误日志，便于与上游 429 区分。

内存模式只在单进程内有效，进程重启不保留窗口。内存时间戳精度沿用秒，Redis 新记录使用毫秒；成功限流不改变计费、退款、渠道选择和禁止重放规则。

## Redis 预占与升级

新成功记录保存在 `rateLimit:v3:MRRLS:{主体}:success`，执行中的预占保存在对应的 `:pending`，均为 ZSET；总次数令牌桶为 `rateLimit:主体` Hash。主体是用户 ID，单独配置限流的分组为 `用户ID:分组`（例如 `rateLimit:v3:MRRLS:{42:vip}:success`、`rateLimit:42:vip`）；同一主体的 success、pending 与旧 List 共用 `{主体}` 哈希标签，保持同槽。Lua 使用 Redis 服务端时间，原子执行准入、续期和完成。

预占租约为 120 秒，每 30 秒续期；已过期预占不能复活。续期失败或名额丢失会取消请求上下文。请求结束时先停止并等待续期退出，再用独立的 2 秒超时上下文完成记录或释放，客户端取消不妨碍清理。Redis 准入错误返回 500，不降级到本机放行；无法确认的预占、释放失败留下的名额由租约回收。

升级时原子准入同时读取旧 `rateLimit:MRRLS:{主体}` List，计入尚在窗口内的成功记录，不清空或改写旧 List。旧时间字符串虽带 `Z`，实际由应用本地时区格式化，因此过渡期应保持原部署时区。旧 List 按原有 TTL 自然退出，新写入只使用 v3 键。当前实现使用仓库现有单节点 Redis 客户端，不支持将含旧键的跨键脚本直接用于 Redis Cluster。

按分组单独计数上线后（按上游 `45fbb149f`），单独配置限流的分组从新键开始重新计数：此前记在用户主体下的总次数与成功次数不迁移、不计入分组，升级后一个窗口内这些分组可能多放行一份；用户主体下的历史仍按原样计入全局请求。蓝绿新旧版本混跑期间，旧版本仍把分组请求记在用户主体下，新版本记在分组主体下，两边计数不共享，混跑期间的实际放行量可能超过单边上限；回滚后旧版本也看不到新版本写入的分组计数。

旧版本不认识新预占，混跑不能保证共同上限；回滚旧版本也不能读取新成功记录。正式发布和回滚须按发布流程协调切换、处理在途请求及剩余窗口。进程暂停或网络分区超过租约时，过期名额可以被其他实例使用，取消操作也依赖处理器响应请求上下文；本机制不承诺这些故障条件下的绝对并发锁。
