# 开票申请

> 定位：现行使用与配置指南。带日期的部署或验证段落保留为当时记录；分类入口见[文档导航](../README.md)。

用户在“充值账单”进入“申请发票”，选择可申请订单并填写发票信息后，点击“提交发票申请”会先显示“确认单张发票金额要求”弹窗。

提醒用户确认报销单位的单张发票金额上限、指定金额及是否需要拆分开票。特殊要求应填写到申请备注，由客服按现有工单流程核对处理；备注不代表自动拆票或已核实的开票金额。

- “返回填写备注”关闭提醒，保留订单选择和全部输入，并聚焦备注框；按 Esc 同样返回备注。
- “已确认，提交申请”才发送开票申请；提交期间禁用重复提交和关闭操作。
- 提交失败保留表单，用户可以修改后重新确认；成功后按原流程关闭申请窗口。
- 每次提交申请都需要确认，确认状态不跨申请保存。

此次确认是提交前的报销需求提醒，不增加发票金额字段，也不改变现有订单资格、金额核对、开具及客服审核规则。

## 查询与批量导出

在管理工单页的“搜索发票抬头”输入公司、单位或个人抬头的一部分，点击“搜索”或按 Enter，即按抬头包含匹配并切换到发票工单。搜索与当前工单状态筛选共同生效；寻找历史已开票记录时可把工单状态设为“全部状态”。“清除搜索”移除抬头条件，切换其他工单类型也会清除条件。搜索后回到第一页并清空原勾选；翻页可保留勾选。客服搜索仍受本人分配及所属工单类型权限限制。

管理员及超级管理员在“发票”类型下勾选工单后，点击“导出所选发票”下载 `.xlsx`，单次最多 500 条，一张申请一行。普通用户和客服不能调用导出接口。搜索结果也可跨页勾选导出，改变搜索、类型、状态、排序或每页条数会清空旧勾选。

导出包含工单号、申请人 ID/用户名、主题、发票抬头、税号、开户行、银行账号、注册地址、联系电话、接收邮箱、申请金额（人民币元）、关联订单 ID/订单号、原始申请说明（包含备注）、工单状态、发票状态、申请时间及开具时间（北京时间）。税号、账号、订单号等均为文本，避免前导零丢失或科学计数法；金额为保留两位小数的数值。用户填写的内容不生成 Excel 公式，长备注超过 Excel 单元格上限时明确失败，不静默截断。

导出使用一致的只读快照，不修改发票或工单状态，不发送通知，也不代表已经开票。可导出待开具、已开具和已拒绝记录，批量开票前须核对“发票状态”和申请说明。所选工单被删除、不是发票或关联信息不完整时，整批失败，刷新并核对后重试，避免漏导。

接口：`POST /api/ticket/admin/invoice-export`，JSON 请求体 `{"ids":[1,2]}`，响应类型为 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`，带附件文件名及 `Cache-Control: no-store`。空选择、超过 500 条、非法 ID 或信息不完整返回 JSON 错误，前端不会把错误响应保存为 Excel。抬头查询复用 `GET /api/ticket/admin?type=invoice&company_name=...`，分页和总数均由服务端过滤；名称中的 `%`、`_` 按普通字符匹配。

局部回归入口为 `web/src/features/tickets/api.test.ts`、`model/ticket_invoice_export_test.go`、`service/ticket_invoice_export_test.go`、`controller/ticket_invoice_export_test.go` 和 `router/ticket_invoice_export_test.go`，均须在 Docker Linux 卷执行。数据库用例使用专用 MySQL 8 随机隔离库。前端构建后可在已有 Playwright 工具镜像内运行 `web/scripts/invoice-recovery.browser.cjs`，使用模拟 API 验证真实路由包弱网恢复、搜索、跨页导出及清理旧选择；该脚本需要先由工作簿测试通过 `INVOICE_EXPORT_FIXTURE=/src/invoice-export-fixture.xlsx` 输出合成样本，不读取线上数据，也不替代实库权限验证。
