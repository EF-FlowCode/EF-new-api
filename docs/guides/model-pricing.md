# 模型定价模式

> 定位：现行使用与配置指南。带日期的部署或验证段落保留为当时记录；分类入口见[文档导航](../README.md)。

全部模型定价集中保存在 `ModelPricing`（version 2）的 `models` 中，每个模型一份记录。普通模型、Embedding、Rerank 共用价格编辑器，支持固定 Token 单价、按次及动态规则；已有按音频秒数的模型保留秒数单位。

没有独立知识库定价优先级。所有模型均可填写图片、音频、缓存和 Batch 价格，无需能力检测先识别模型。配置价格不会授予供应商未支持的端点或 Batch 能力；执行条件见[知识库模型说明](knowledge-base-pricing.md)和 [Embedding Batch File](knowledge-batch.md)。

## 已迁移的结算参数

倍率定价以输入倍率为基准，通过 `ModelRatio`、`CompletionRatio`、`CacheRatio` 和 `CreateCacheRatio` 计算输入、输出、缓存读取和缓存写入价格。

- 迁移保留原始数值、默认规则和结算算法；界面统一显示绝对价格。仅打开并保存不会切换计费算法。内部倍率不代表另一份定价权威。
- 音频输出价等于输入基价 × 音频输入倍率 × 音频输出倍率，不能仅乘最后一项。
- `CreateCacheRatio` 是缓存写入倍率；现有兼容链路仍会为 Claude 1h 缓存写入应用历史换算规则。
- 模型广场显示输入、输出、缓存读取和缓存写入价格；没有配置的缓存项显示为不可用。

## 固定 Token 单价

固定 Token 单价模式的内部标识为 `flat_price`。管理员直接填写以下美元价格，单位均为每 100 万 Token：

- 输入
- 输出
- 缓存读取（可选）
- 缓存写入 5m（可选）
- 缓存写入 1h（可选）
- 图片输入、图片输出、音频输入、音频输出（均可选）
- Batch 输入（可选，独立于同步表达式；执行需有兼容渠道）

新固定单价保存到模型记录的 `expression` 中，`mode` 为 `flat_price`，复用表达式预扣和结算。5m 与 1h 独立；可选字段留空表示不拆分该维度，`0` 表示显式免费。Batch 保存为 `batch_input_ratio`（单价除以 2）。修改旧模型同步价格会保存新的固定单价规则；仅调整 Batch 不重写同步规则。

## 阶梯计费

阶梯计费的内部标识为 `tiered_expr`，用于上下文长度、请求参数、时间段等会改变价格的动态规则。只有此模式在模型广场标记为“动态计费”；`flat_price` 按普通固定 Token 单价展示。

## 统一金额单位

所有新生成或保存的计费表达式使用 `v2:`，最终结果是**分组倍率生效前的美元计价金额**，与现有按次 `unit_price` 使用同一基础金额单位。前端显示人民币、美元或自定义币种的设置属于展示换算；本次不会更改汇率或把美元价格解释成人民币。

| 计费方式 | v2 表达式示例 | 本次基础金额 |
| --- | --- | --- |
| 每百万输入 Token 2 美元，输入 1000 Token | `v2:tier("tokens", p * 2 / 1000000)` | 0.002 美元 |
| 每秒 0.01 美元，插件确认生成 5 秒 | `v2:tier("video", u("seconds") * 0.01)` | 0.05 美元 |
| 每次 0.03 美元 | `v2:tier("call", 0.03)` | 0.03 美元 |

宿主将金额乘以 `QuotaPerUnit` 和分组倍率，再按原路径舍入。默认 `QuotaPerUnit=500000`，表示 1 美元对应 500000 个内部额度；例如 0.05 美元、分组倍率 0.8，最终为 20000 quota。quota 仍是内部整数额度，不是元或美分。

固定 Token 价格表格继续按“美元／百万 Token”填写；编辑器负责生成除以 1000000 的表达式，可视化条件中的 Token 数量保持原值。原始表达式编辑时必须明确写 `v2:`，无前缀和 `v1:` 仍按旧格式导入，保存时自动换算。

迁移将旧表达式的**整体结果**除以 1000000，例如 `tier("base", p * 2)` 变为 `v2:(tier("base", p * 2)\n) / 1000000`（`\n` 表示实际换行）。不修改内部常量、条件、舍入、显式零价或分组倍率，不猜测模型名称和价格量级。旧任务中的 `param()` 继续读取原请求；金额迁移不自动把它替换为插件 `u()`。

旧在途请求的表达式快照继续按旧版本换算；新规则与旧快照不会重复除以一百万。迁移在同一事务内保存 `ModelPricingAmountMigrationV2`，只记录原定价配置及来源/目标 SHA256，不复制凭据选项；重复启动不重复换算；回滚后再次迁移时保留最早原值，本次来源记入 `latest`；该记录与 `ModelPricingTaskRulesV1` 一样不可经 options API 写入。非法旧规则会阻止迁移，不静默跳过停用或孤立模型。来源记录用于审计，不替代发布前的完整备份。

本次工作区已完成金额单位统一及下述提交用量 `u()` 接线，尚未发布。插件专属结构化规则、旧价迁移预览／确认工具及迁移后的完整回退顺序已接入，尚未迁移业务库；全局绑定别名、公共 Responses/Video 协议及上线验收仍按上游缺失清单单独追踪。

## 插件任务用量 u()

任务动态表达式可用 `u("字段名")` 读取**固定生产插件提取并经宿主校验的提交用量**。例如 `v2:u("seconds") * 0.01` 表示每秒 0.01 美元，插件返回 5 秒时基础金额为 0.05 美元；不会再次乘旧时长或分辨率倍率。`param()` 仍读取客户原请求，客户端提交的 `usage` 对象不能替代 `u()` 的事实。

- 编辑器从 `/api/pricing` 的 `billing_usage` 显示当前模型字段、类型、单位、枚举、示例和固定版本来源。字段取自映射末端模型的 `UsageForModel`，不使用全局激活版本。仅改模型名称时也重新匹配字段；Token 估算器不模拟插件用量。
- 字段名只能为规范的字符串字面量，必须使用 `v2:`。动态 key、`u` 函数引用、通过 `$env` 间接访问函数，以及未执行分支中的未知字段都会被拒绝。数值、布尔与枚举按 schema 校验，缺失事实不当作 0；非法类型、负值、非有限数及超过宿主上限的用量拒绝执行。
- 新增／修改 `u()` 规则或启用停用的表达式时，后台校验所有启用渠道。同名模型有未绑定渠道、不同插件或不一致的字段定义时，不允许保存新规则；提示先处理生产绑定。普通 Token 和固定 Token 单价不能使用 `u()`。
- 插件暂停不阻止启动、读取、原样保存或无关配置修改；任务实际执行时始终按选中渠道的固定绑定复核。展示缓存不能替代运行时校验。
- 提交时保存表达式、版本、额度换算、分组、用量和插件身份快照。之后改价、改映射或幂等重放不重算该任务；完成用量表达式重算尚未开放。

### 插件专属定价与映射末端回退

系统设置的模型定价中新增“插件任务定价”。先选择公开模型名或固定绑定声明的末端模型名，再选择插件，填写 `v2:` 金额表达式。规则只作用于该插件的任务入口，普通 Token 请求不读取它。移除专属价格后按下表重新选择价格；移除不会删除通用模型价格。暂停规则可查看、编辑和移除，新建／修改必须有可验证的固定绑定与离线 schema。启用中的目标不能移除其必需的明确规则；孤立规则的处置仍受迁移预检约束。

唯一存储仍为 `ModelPricing` version 2，`task_expressions` 的值改为 version 1 结构化规则。例如：

```json
{"alibaba":{"version":1,"kind":"amount","expression":"v2:u(\"seconds\") * 0.01"}}
```

它保存在 `models["video-alias"].task_expressions`。`billing_setting.task_expressions` 是管理 API 的“模型名 → 插件 key → 规则”投影，不单独持久化。旧字符串仍可导入，保存为同表达式的 `amount`；启动格式升级在同一事务保存 `ModelPricingTaskRulesV1` 原文和来源／目标摘要，重启不重复转换或覆盖记录。普通改价保留任务规则，模型重命名携带全部规则；新名称仍须通过固定绑定校验。

| 规则 | 金额与结算合同 | 编辑行为 |
| --- | --- | --- |
| `amount` | `v2:` 表达式返回分组前 USD；提交固定总价，最终四舍五入，不再乘 provider 维度 | 编辑总金额表达式 |
| `unit_price` | USD 单价；先乘 `QuotaPerUnit` 和分组后截断，再按原顺序乘 provider 维度并截断；WAN 保留完成时长结算 | 编辑 USD 单价，保留计量／取整／完成阶段 |
| `token_completion` | 保存原 `model_ratio`、是否配置及 Token 完成合同，避免浮点反算改变原值 | 按当前 `QuotaPerUnit` 展示 USD／百万完成 Token；仅实际编辑才换算回内部系数 |

单位价／Token 规则绑定固定插件的归一末端，并声明 `dimensions`（`none` 或 `provider_v1`）及 `settlement`（`submit`、`wan_duration` 或 `tokens`）；未知版本、非法组合或不匹配的末端拒绝。页面查看、切换页签或无修改保存不会将这些规则变为总金额表达式。点击“改为总金额”是明确改价，会改变取整及完成结算语义。

插件任务价格语义：

- **默认跟随模型价格**：模型没有该插件的专属价格时，任务实时使用模型自己的通用价格（表达式 `model_original`，或单价／默认价／倍率 `legacy_original`）。改模型价格后，下一次任务请求即按新价计费，无需再改“任务价格”。
- **单独设置**：`task_expressions[模型][插件]` 存在时只用它（`plugin_original`），覆盖模型通用价。
- **迁移后的保护**：`task_priority_version` 为 0（缺省）和整批迁移成功后的 1，上述两条完全相同；版本 1 只多一条保护：模型自己没有价格时，不隐式套用映射末端的通用价格（`model_mapped`），只允许末端的插件专属价（`plugin_mapped`），否则拒绝并要求设置价格（`explicit_task_rule_required`）。

| 优先级版本 | 查价顺序 |
| --- | --- |
| 0 | 插件原名 → 通用原名表达式／原单价／默认价／倍率 → 原名缺价时插件末端 → 通用末端表达式 |
| 1 | 插件原名 → 通用原名表达式／原单价／默认价／倍率 → 原名缺价时插件末端；其余情况拒绝，要求明确规则 |

选中的规则非法时直接拒绝，不继续尝试更低优先级（如 `flat_price` 的 Token 价无法按次计价，跟随时也拒绝）。零价算已有价格；自用模式下所有模型都有默认倍率，因此都跟随该倍率。插件 key 来自实际渠道的固定生产绑定，不能由客户指定其他插件套价。普通管理保存／导入不能自行改变优先级版本。

#### 旧任务价格迁移

Root 在插件任务定价页先预览，再确认。`GET /api/option/task_pricing_migration` 只生成清单，`POST` 同路径携带 `{ "source_hash": "预览返回值" }` 才执行迁移。预览从同一锁定数据库快照读取全部定价、渠道／映射、启用和停用的固定绑定及对应源码；不读取渠道密钥，不请求供应商，不依赖插件 Manager 已启动。

迁移**不再复制模型价格**：来自模型自身通用价格的条目标记为 `follows_model_price`，不写入 `task_expressions`，迁移后仍实时跟随模型价格（单价保留原两段截断及完成结算）。已有插件专属规则保留；若它与按模型当前价格推导出的规则完全相同（通常是旧版迁移复制品），从候选中删除并标记 `converted_to_follow`，不同的保留并标记 `override_differs_from_model`，供复核。原名缺价、依赖映射末端价格的条目仍写成明确插件规则。保留普通同名价格和分组，不回填历史任务。

插件专属孤立规则、任务渠道空模型列表、已声明任务缺少固定绑定、固定源码缺失、映射错误、跨末端合同冲突及依赖用户允许未配价的任务项都会阻止整批迁移。未引用普通价格原值保留；无绑定且未被对应插件声明的条目保留价格并标记任务不可用，不自动绑定或删除。工具没有“忽略阻塞”入口；须逐项明确处置，不能把尚未确定的项当成不需要。渠道、价格、绑定或分组等输入变更后，旧预览摘要失效，必须重新预览。

确认将候选 `ModelPricing`、`task_priority_version=1` 和 `ModelPricingTaskMigrationV1` 原价／摘要／清单同事务保存；失败全部回滚。重复确认不覆盖迁移后的管理员改价，启动时缺少有效迁移来源记录会拒绝已切换优先级的配置。该记录用于审计，不替代数据库备份。

2026-10-04（旧版"复制价格"迁移语义，改为跟随后需重跑）已在冻结线上配置的独立 baseline 克隆执行预览和确认：222 个模型价格保留，8 个任务条目 × 36 分组的迁移前后 576 次 HTTP 扣费一致，同候选重启及重复确认幂等通过；独立合成环境的浏览器读改保存和改价后扣费也通过。生产业务库尚未迁移。真实发布仍必须通过完整 baseline 克隆升级及全部门禁；普通价格快照比对不会自动放行优先级切换，见发布合同。

`billing_usage.plugins` 按插件分别返回字段定义；同名普通渠道或其他插件不阻止独立的插件规则。同插件字段冲突仍拒绝；聚合保留所有已知末端用于校验，无法确定绑定目标时拒绝该插件的新／修改规则，不能忽略未知目标。同一绑定渠道上可证明不属于插件的普通文本模型不参与插件规则校验。原样／无关保存、删除仍不要求插件运行。

`/api/pricing.task_pricing` 返回每个插件及不同末端的生效来源，设置页面显示该来源；普通价格栏继续表示通用定价。新增任务价格快照记录 `price_source`、`price_model`、`price_plugin` 及实际选中的结构化 `price_rule`，重放或完成使用已保存合同。旧任务没有这些可选字段也不会被重新定价。

### 在途任务的完成价格

插件任务按 Token 完成计费时，新任务冻结提交时的模型倍率、实际分组／客户等级倍率和附加倍率；之后改价、调组、删除配置或重启都不影响该任务的结算。提交时允许未配置倍率的任务也不会因后来新增倍率而突然改为 Token 重算。供应商成功和 Token 数持久化后，资金失败只重试同一笔本地结算。

旧任务没有此快照时保持旧结算路径，尚未统一迁移为新规则。新路径也修正了旧完成计算可能漏用提交时客户等级折扣的问题，不能把该修复当作全部旧价格等价迁移完成。具体字段、待结算和人工核对限制见完成 Token 计费快照。

## 一次性迁移与同步

任务迁移按固定绑定源码和映射末端判断适用范围。OpenAI、Alibaba、Gemini 等渠道类型不代表渠道内每个模型都是任务。无绑定且未被对应插件声明的条目标记为 `preserved_unbound`：价格保留，任务协议仍不可用，这不表示已经认证为文本模型。未引用价格标记为 `preserved_unreferenced`，保持原始值；已声明任务缺固定绑定、插件专属孤立规则、源码缺失或映射冲突仍阻塞迁移。

确认任务迁移后，有通用价格的模型照旧跟随该价格；原名缺价时不隐式套用映射末端的通用价格，需要末端插件专属价或明确规则。缺价及合同不匹配在预扣、发送供应商请求之前拒绝。渠道启用、单项/批量映射修改、绑定启用和价格保存均校验已启用目标，失败回滚。暂停绑定可先配置明确价格再启用，普通文本模型不要求任务规则。

通用价格和插件专属价格具有不同适用范围；没有插件专属价格时修改通用价格即对插件任务生效，已设置的插件专属价格不随通用价格变化。页面展示当前生效来源和任务单价。金额表达式仍为分组前 USD，单价保留其单位及原截断顺序，完成计费继续使用提交快照；历史任务不回填或按新价格重算。

任务价格编辑器通过 Root-only `GET /api/option/task_pricing_usage` 读取固定源码声明，包含暂停渠道的模型、schema 和价格来源，便于先定价再启用。此接口不返回密钥、端点或源码，也不授予运行任务的权限；公开价格接口保持原有可见范围。

`migrate` 角色或独立主实例把全部 11 个旧定价选项收拢到 `ModelPricing`，并在同一事务内删除旧选项。包含停用模型、辅助配置和未生效表达式，不只处理公开列表或知识库模型；分组倍率不改。旧倍率和按次价格保留原数值、精度和生效规则；全部旧表达式转换为下述 v2 金额单位，包含未生效规则。已有 version 1 文档同样升级，不只处理旧独立选项。

API 中的倍率字段仅作计算投影和导入格式。批量提交汇总到 `ModelPricing`，不重新生成旧数据库选项；同次更新不得混用 `ModelPricing` 与投影字段。契约为 `eflow-rolling-v8`，不支持旧 worker 混跑，生产需维护迁移，并先通过本地真实升级门禁。

- 切换定价模式时，后台会清理同一模型的冲突配置。
- 编辑或重命名模型时，固定单价模式和表达式会随模型配置同步更新，旧模型名下的配置会被移除。
- 服务启动时会幂等扫描旧数据：如果 `tiered_expr` 的整个表达式严格为单个 `tier(...)`，内容只包含 `p`、`c`、`cr`、`cc`、`cc1h`、`img`、`img_o`、`ai`、`ao` 与非负数字的乘积之和，并且同时包含 `p`、`c`，则只将该模型的模式迁移为 `flat_price`，此模式识别不修改表达式；独立的金额迁移会按下述规则包装旧表达式。
- 时间倍率、条件、多阶梯、请求参数等表达式仍使用 `tiered_expr`，也统一为 v2 金额单位。
- `/api/pricing` 与开启后的 `/api/ratio_config` 都会返回表达式计费模式和表达式。与普通 New API 同步时，原有倍率字段保持兼容，旧固定表达式会在比较和导入前归一化为 `flat_price`。
- 上游价格同步按模型保持倍率、按次固定价和表达式计费互斥：选择普通倍率或按次固定价会清理该模型原有的 `flat_price`/`tiered_expr` 模式和表达式；选择固定 Token 单价或阶梯表达式会清理该模型原有倍率和按次固定价。所有相关定价选项通过批量接口原子保存。

## 时间规则编辑与原合同保护

动态计费编辑器切换可视化/表达式模式只改变展示，不改写已有计费表达式或请求规则。不能可视化解析的规则也保留原文；仅打开、切换模式、聚焦后离开输入框或原样保存，不产生价格变更。

- 已存日内 OR、跨夜 AND 等非标准组合保留原运算符，并继续显示警告；公开价格不为它们生成误导性时段摘要。
- 新增或明确修改一条时间条件时，按起止值重新生成该条件：日内/等值用 AND，跨夜用 OR。同组、其他组未编辑条件的原运算符保留。
- 只改倍率或普通价格，不顺带修正时间范围。外部刷新以新配置为准；原始表达式编辑和应用预设仍属于显式修改。

## 配置同步与定价缓存

后台默认每 60 秒同步数据库配置，成功发布定价选项后使价格缓存失效，下次读取重新计算。配置发布与价格刷新可以并发发生：配置表与传统配置值更新结束后，必须先释放配置锁，再执行定价缓存失效；价格刷新会在持有定价锁时读取模型上下文配置，反向嵌套两把锁会导致模型广场及读取配置的状态、公告接口共同阻塞。

配置更新仍由 `optionMutationMutex` 串行化，缓存失效在更新返回前完成；这不意味着所有配置域与定价数据具有跨域原子快照。该锁顺序由 `TestPricingRefreshCanReadOptionsDuringConcurrentPublication` 并发回归覆盖。
