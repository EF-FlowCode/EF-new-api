# 客户等级、令牌分组与充值优惠

> 定位：现行使用与配置指南。带日期的部署或验证段落保留为当时记录；分类入口见[文档导航](../README.md)。

管理员统一从“客户 → 客户等级与优惠”维护相关规则。

- 客户等级写入 `users.group`，用于区分 VIP、SVIP 等客户身份。
- 管理员授予的附加客户等级写入 `users.additional_customer_tiers`；模型与令牌权限合并主等级和全部附加等级的规则。
- 令牌分组写入 `tokens.group`，用于选择渠道路由和基础计费倍率。
- 客户等级充值优惠使用 `TopupGroupRatio`。
- 客户等级对指定令牌分组的专属倍率使用 `GroupGroupRatio`。
- 充值档位优惠使用 `payment_setting.amount_discount`。

实际充值价格按以下规则计算：

```text
充值额度 × 单价 × 客户等级充值倍率 × 充值档位倍率
```

例如客户等级倍率和充值档位倍率均为 `0.9` 时，最终支付倍率为 `0.81`。

定价配置继续保存在现有 `options` 表中。应用启动迁移会为 `users` 表补充 `additional_customer_tiers` 文本列；无需手工建表。用户编辑页的主等级和附加等级都只读取客户等级选项；API Key 编辑页仍读取令牌分组。

充值只使用 `users.group`。可用模型、令牌创建、请求鉴权、自动分组与模型广场价格，则使用主客户等级和 `additional_customer_tiers` 对应规则的并集。移除附加等级后不会删除既有令牌，但该令牌若已不属于有效分组，将显示失效提示并拒绝请求。
同一令牌分组在多个有效客户等级下存在专属倍率时，模型广场和实际计费都使用最低倍率。

## 按模型 RPM 限流

用户总请求次数和成功次数的预占、失败释放及 Redis 过渡规则见[模型请求次数限流](model-request-rate-limit.md)。

管理员可在“系统设置 → 请求限制 → 限流”中开启按模型 RPM 限流。每条规则包含模型默认 RPM，以及可选的客户等级覆盖值。

- 计数维度为“用户 ID + 原始请求模型名”，不同用户、不同模型分别计数。
- 同一用户的多个 API Key 共享同一个模型 RPM 额度。
- 主客户等级和全部附加客户等级都会参与匹配；同时命中多个覆盖值时取最高 RPM。
- 令牌计费分组不参与客户等级 RPM 匹配。
- 未配置的模型不受按模型 RPM 规则限制。
- Redis 启用时使用跨实例共享的 60 秒滑动窗口；无 Redis 时仅在当前实例内计数。

管理界面以 `GroupRatio` 中的名称作为令牌分组唯一来源。用户可选分组、自动分组、客户等级专属倍率和特殊可用分组规则只能搜索并引用已有令牌分组，避免手工输入名称不一致而导致无法计费。

客户等级管理界面以 `TopupGroupRatio` 中的名称作为客户等级唯一来源，倍率 `1` 表示充值不打折。专属定价和特殊可用分组规则跟随左侧选中的客户等级维护；历史规则引用了未登记等级时，页面会提供“待补录”入口，不会静默隐藏数据。

## 管理员创建用户的角色校验

创建用户接口只接受本地角色集合：访客 `0`、普通用户 `1`、客服 `5`、财务 `7`、管理员 `10`、Root `100`，
并继续要求新用户角色小于操作者角色。因此管理员不能创建管理员或 Root，Root 不能创建另一个 Root。
非法角色在写入数据库前被拒绝；此规则不改变已有账号、OAuth/OIDC 登录或客户等级配置。
