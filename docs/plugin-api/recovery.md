# 插件提交恢复与人工核对

> 定位：现行恢复与人工核对合同。部署快照不代表异常资金路径已完成生产验收；范围见文末记录。返回[Task Plugin 总览](README.md)。

已实现，并于 2026-09-17 随 eflow v5 维护升级部署。覆盖全部 11 个插件的统一提交入口，实际使用仍受插件开关和渠道绑定约束；普通聊天、音频及独立 TTS 不在此合同内。后台恢复只处理本地持久证据，不重新发送生成请求。

## 提交与重放

客户端可在原提交请求中携带 `Idempotency-Key`（最多 191 字节）。作用域为用户、Token、请求路径；指纹包含原模型、规范化 JSON 和上传文件的名称、类型、内容摘要。同 key、同内容返回原任务；同 key、不同内容返回 HTTP 409。没有 key 的独立请求不做去重，未完成记录不自动过期。

发送前在同一 MySQL 事务写入 Task、固定源码/引用、提交记录、预扣审计，并扣减钱包与 Token、更新统计。失败不发送 HTTP。发送权通过状态 CAS 领取，最多自动提交一次；所有错误禁止自动换渠道重试。

| 状态 | 含义与资金处理 |
| --- | --- |
| `SUBMITTING` | 已预扣，尚未领取发送权；超过准备期限仍未发送时原子退款 |
| `SUBMIT_UNKNOWN` | 已领取发送权，可能被供应商受理；保留预扣，不普通超时退款、不自动重发 |
| `SUBMITTED` | 已解析并持久保存上游 ID，进入固定插件轮询 |
| `BILLING_PENDING` | 已确认成功，缺结算依据或资金事务待重试；保留结果和预扣 |

准备和发送保护期限各为一分钟。后台重试间隔与人工操作锁分开，反复解析失败不会无限延长人工等待。准备过期退款只允许 `prepared` 阶段，不能取消已领取发送权的任务。HTTP 执行器限时 10 秒，结束后使用独立上下文留存响应。

未知提交返回 HTTP 409、`plugin_submission_unknown`、`data.task_id` 和 `X-Task-ID`，公共视频查询状态为 `unknown`。复用原 key 查询原任务，不换 key 重提。已失败任务的 key 仍保留，返回 `plugin_submission_failed`。Suno 已受理重放保留原生响应格式和公共任务 ID。

响应已经保存时，重启后使用任务固定源码重做本地解析并保存上游 ID；不调用生成接口。发送后断连、响应保存失败、HTTP 非 2xx 或解析失败均保守留待核对。非 2xx 不足以证明未受理，因此本版不据此自动退款。无上游 ID、无已保存响应时，没有通用的自动查找合同。

请求解析证据和响应 JSON 分别限 2 MiB，仅存私有提交表，管理 DTO 不返回；接受或退款后清空这两项，保留幂等指纹与审计。保留任务原凭据和源码引用以支持后续查询。

## Root 核对流程

任务日志页提供“待核对任务”入口和逐行核对按钮，仅 Root 可见。后端每个路由均执行真实 RootAuth，预览和确认还核验数据库中的 Root 身份。

1. 刷新任务，核对状态、当前预扣、历史单位额度、完成时长和审计。仍在发送保护期限内不能确认。
2. 未知受理可补真实上游 ID：使用固定插件、原任务凭据执行只读查询，要求返回可识别状态；插件输出上游 ID 时检查一致性，批查询只接受一个匹配结果。同渠道、相同凭据和上游 ID 不能关联两个本地任务。**部分插件的查询输出不携带 ID；查询成功也不证明该任务属于本次请求，Root 必须另行核对归属。**
3. 有明确未受理证据时选择退款。成功待结算不允许改失败退款。
4. 待结算可补缺失的完成事实或历史价格快照；非法事实可纠正，已有效的字段、已保存价格和已确认完成事实不能覆盖。历史价格只能据记录填写，不能从当前售价猜测。额度单位为内部 quota，按秒模式需要分辨率倍率；固定总价模式填写已核实总额度。
5. 填写理由、证据摘要并确认归属与计费依据，先预览前后额度及差额，再确认操作。

预览有效期五分钟，绑定操作者、任务 revision、状态及预扣额度。确认在同一事务中执行状态 CAS、钱包/Token 差额、统计及审计；资金或审计写入失败全部回滚。并发重复确认同一操作只生效一次；旧预览和后台旧快照不能覆盖已经确认的任务。过期、并发变化返回 409，刷新后重新核对。操作仍受插件开关约束，暂停不会授权跳过固定源码校验。

新版本按 Token 完成计费的任务具有独立的提交价格快照和已确认 Token 数。详情只读显示模型、分组、附加倍率与 Token 数；已有快照时页面不提供历史固定／按秒价输入，后端也拒绝以该字段覆盖，即使价格快照非法或当前尚未标为结算就绪。有效快照可以经原预览／确认流程结算，重复确认仍只计费一次；未知版本或损坏快照保持待核对，不按当前价格修补。旧 WAN 补缺失时长／分辨率／历史价格流程保持。

成功 Token 结果先进入 `BILLING_PENDING`；钱包或 Token 事务失败后只重试已存结果的本地结算，单查与批查均遵守此约束。具体合同见完成 Token 计费快照。

## 管理 API

前缀 `/api/plugin/task`；`:task_id` 为数据库数字主键，区别于客户端公共 Task ID。

| 方法与路径 | 用途 |
| --- | --- |
| GET `/runtime/reviews?after=0` | 按数字 ID 升序，每页最多 50 条待核对/待结算任务；下一页传最后一个 ID |
| GET `/runtime/tasks/:task_id/review` | 脱敏详情、可补字段、保护截止时间、最近 50 条已应用审计 |
| POST `/runtime/tasks/:task_id/review/preview` | 创建预览；请求 JSON 限 8192 字节 |
| POST `/runtime/reviews/:operation/confirm` | 按预览操作 ID 确认，原操作者可幂等重试 |

预览公共字段：`revision`、`action`（`attach`/`refund`/`settle`）、`reason`（最多 1000 字节）、`evidence`（最多 4000 字节）、`confirmed: true`。按动作附加 `upstream_id`、`seconds`、`resolution`、`billing`。`billing` 为 `{version:1, mode:"duration"|"fixed", base_quota, resolution_ratios}`。详情和列表不返回私密请求、响应、源码或凭据；理由和证据由操作人填写，不应粘贴密钥或完整请求。

## 审计、验证与发布

同库 `task_plugin_reviews` 是预扣/未发送退款/人工操作的可靠审计。用户消费日志在资金事务之后尽力写入 `LOG_DB`，不重复统计；日志故障或事务后崩溃可能漏日志，本版没有全站日志 outbox。

新增 `task_plugin_submissions`、`task_plugin_reviews` 和 `tasks.revision`，部署契约为 `eflow-rolling-v5`。旧 worker 可能错误处理未知受理任务，从旧契约升级须同步更新 Web/worker，不能混跑或普通回切。eflow 已完成备份、隔离迁移验证、正式迁移及发布，见 发布说明。部署后已完成一次 Happyhorse 文生视频真实提交、轮询、下载与扣费检查，见 统一宿主；未知受理恢复及人工资金核对异常路径仍未进行生产验收。
