# 模型性能指标口径

> 定位：现行开发与行为约束。带日期的部署或验证段落保留为当时记录；分类入口见[文档导航](../README.md)。

模型广场详情及分组监控中的单模型首字、TPS、平均延迟、成功率和近 24 小时趋势来自 `perf_metrics` 聚合数据。

## 成功与失败

- 请求在重试后最终成功，计为一次成功样本。
- 请求在所有重试结束后仍失败，计为一次失败样本。
- 中间重试失败但最终恢复的请求，不会额外计为失败。

原生 Responses 流的 EOF 或 `[DONE]` 不等于模型已成功完成；尚未收到有效终态时会返回错误。终态、0/1 Token 和用量结算的关系见 [Responses 流终态与用量](responses-stream-accounting.md)。

## 可用率排除规则

模型性能指标与分组监控共用以下配置：

- `availability_exclude_models`
- `availability_exclude_status_codes`
- `availability_exclude_keywords`

命中任一规则的请求会从统计中整条排除，既不进入请求总数，也不进入成功数或失败数。关键词按不区分大小写的子字符串匹配。

排除规则只影响配置生效后写入的新样本。历史 `perf_metrics` 仅保存聚合计数，不包含状态码和错误内容，因此不能按新规则追溯重算；旧数据会随统计窗口自然滚出，或在清理历史指标后消失。

## 分组监控手动刷新

`POST /api/monitoring/admin/refresh` 保持管理员鉴权和关键操作限流。单实例未配置 Redis 时由本地聚合循环接收；配置 Redis 时写入共享的可合并刷新信号，由唯一主节点/worker 每秒检查，加载最新配置后聚合。连续点击会合并，聚合期间的新请求保留到下一轮。

HTTP 202 表示已接受刷新请求，后台繁忙或暂不可用时仍需等待；它不表示数据已经更新。Redis 不可用时返回 HTTP 503 和 `success:false`，不会报告已触发。本地非 Redis 模式聚合忙时仍返回 429。刷新不会改变已有模型性能指标和分组监控各自的统计口径。平滑部署的 worker 升级要求见 平滑部署。

## 分组监控统计口径

每轮聚合读取可用率窗口内的 Redis 分钟桶：成功数取自桶计数，错误数按当前排除规则从 `logs` 现算。任一查询或 Redis 扫描失败时放弃本轮，保留上一轮快照与历史，不会把错误数当作 0 写成 100%。关闭消费日志不影响成功计数。平均响应时间的分母是窗口内全部请求（含命中可用率排除的请求），与分子口径一致。

本轮窗口内没有请求的渠道，其统计置为"无数据"（可用率、缓存命中率显示为 —，标记离线），更新时间保留为最后一次有数据的时间；渠道记录不删除。管理员分组详情的渠道表显示渠道启用状态、可用率、缓存命中率、首字时间和统计更新时间。

模型性能指标只在处理请求的进程内存中累计并定期写入数据库，未写入前的数据仅本实例可见。

## 故障时段

页面显示的“故障”数量是成功率低于 100% 的“分组 × 聚合时间桶”数量，不等同于失败请求数量。同一时间桶内两个分组都失败会计为 2 个故障。时间桶粒度由 `perf_metrics_setting.bucket_time` 配置。

## 分组监控模型明细

每个分组以一张紧凑卡片展示：顶部为分组状态、倍率、更新时间、可用率、首字、缓存率及历史趋势，管理员还可查看渠道数量和打开详情；下方列出近 24 小时有采样的全部模型，不默认折叠。

桌面端（沿用项目 `md` 断点，视口宽度 ≥768px）按模型数量分栏：1–4 个模型单栏，5 个及以上均分为双栏，奇数时左侧多一行。阅读顺序为先左栏后右栏，每栏重复表头；不再根据卡片宽度设置额外分栏门槛。手机端始终单栏，两段模型表按原顺序上下排列；模型表空间不足时可在表内横向滚动。分组倍率仍按实际配置展示为倍率，不将其直接换算成货币价格。

- 首字为有效流式首响应样本的平均耗时（秒），缺少有效值时显示 `—`。
- 延迟为请求总耗时之和除以请求数（秒）；失败样本也按现有性能统计口径计入。
- 吞吐为输出 Token 总数除以对应生成时间总和（t/s），缺少有效值时显示 `—`。
- 成功率为成功请求数除以请求总数。先合并原始计数再计算，不直接平均不同桶的百分比。
- 趋势按小时合并原始采样桶，悬停或键盘聚焦可查看时段和各指标；空时段保持灰色，真实失败的 `0%` 保留为红色。窗口边缘只包含符合时间范围的采样桶，不回填不存在的历史。
- 颜色阈值为成功率 ≥99% 绿色、≥95% 浅绿、≥80% 黄色、≥50% 橙色，其余红色。

分组可用率沿用分组聚合配置和历史数据，单模型成功率采用近 24 小时的性能样本，两者可能不同。模型性能的排除规则无法追溯重算，见上文。

模型明细每 60 秒自动刷新；管理员手动刷新也会重新读取模型明细。明细加载失败不会隐藏分组状态；有上次数据时保留并明确标记刷新失败。没有样本的模型不会生成虚构指标。跨实例未落盘样本的可见性沿用现有模型性能查询：数据库累计值加本请求实例内尚未刷新的计数，其他实例样本需等待原有刷盘周期。

### 批量只读接口

- `GET /api/monitoring/public/models`：沿用公共监控入口，可匿名访问。
- `GET /api/monitoring/admin/models`：需要管理员权限。

接口不接受扩大范围的模型、分组或时间参数，仅读取服务端 `monitoring_groups` 配置中的分组。空配置返回空对象，不查询全库。单次批量查询有 10 秒超时，不新增表结构。响应只包含模型名称、分组、平均值和成功率，不包含渠道信息、请求量或 Token 总量。

成功响应为 `{ "success": true, "data": { "groups": { "分组名": [模型明细] }, "start_time": 秒时间戳, "end_time": 秒时间戳, "bucket_seconds": 3600 } }`。

模型明细字段：`model_name`、`group`、`avg_ttft_ms`、`avg_latency_ms`、`avg_tps`、`success_rate` 和 `series`。`series` 中每项为小时起点 `ts` 及同名四项指标。窗口固定为查询时刻往前 24 小时，源桶按起点筛选；小时展示桶与窗口边缘相交时，可能有 25 个展示位置。无样本的小时不返回，客户端按窗口补灰色空位。

读取失败返回 HTTP 503 和 `{ "success": false, "message": "Failed to load model monitoring data" }`。
