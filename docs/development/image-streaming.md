# 图片请求与流式响应

> 定位：现行图片入口行为说明。早期三条提交的排障、代码片段和验证快照保留在图片流补丁记录。

## 图片数量与 Ali 响应格式

生成和编辑入口在价格计算、预扣之前校验图片数量，JSON 与 multipart 请求均适用。
顶层 `n` 缺省或为 `0` 时保留旧兼容值 `1`；有效数量为 `1`–`128`，负数、非整数、
溢出或超过上限返回客户端参数错误。该上限不是供应商保证支持的单次生成数量。

Ali 的 `parameters.n` 存在且非 null 时作为有效数量，必须为 `1`–`128`；显式 `0` 不使用缺省。
校验后的数量用于初始预扣与 Ali 输出请求，`parameters` 未带 `n` 时沿用顶层数量。
其他供应商的自定义 `parameters` 不按 Ali 合同解析。本次不改变已有价格配置或引入上游新的图片计费变量。

Ali 的 `response_format` 从已解析的图片请求读取，支持 `url` / `b64_json` 的原有转换；
multipart 编辑入口也记录该字段，不再依赖未赋值的 Gin context 字段。

## 流式透传范围

`/v1/images/generations` 与 `/v1/images/edits` 支持图片请求的 `stream:true` 与 `partial_images` 透传；上游仍须支持对应图片 SSE 协议。该说明不扩展 Chat、Responses、Claude 或 Gemini 的协议能力。

客户端请求流式时，等待上游响应头期间先发送 SSE 头并维持心跳；取得响应后等待前置心跳退出，再交给图片流 handler。响应阶段使用 `ForcePing` 保持流内心跳，优先级为 `DisablePing > ForcePing > 全局开关`。心跳用于缓解中间链路空闲超时，不保证供应商成功、网络持续可用或所有代理配置都兼容。

不传 `stream` 或传 `false` 时沿用非流式路径。若上游实际返回 `text/event-stream`，响应阶段可转入图片流 handler，但此前没有前置心跳。请求流式而供应商返回非 SSE 时不能保证得到有效图片结果，应先确认渠道的协议支持。

流内图片事件透传和最终 usage 提取沿用图片 handler。断连后的原始排障记录不构成安全重试或不重复计费保证；重新提交前须核对受理、结果和扣费情况。
